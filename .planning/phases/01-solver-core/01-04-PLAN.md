<task type="auto">
  <name>Task 2: Implement core game tree builder</name>
  <files>src/lib/solver/gameTree.ts</files>
  <action>
Implement lazy game tree generation:

1. `buildInfoSetId(player: Player, hand: CanonicalHand, history: string[]): string`
   - Combines player, canonical hand, and action history into unique ID
   - Format: `{player}:{canonicalHand}:{history.join(',')}`
   - This is what CFR uses to lookup/store regrets

2. `buildNodeId(history: string[]): string`
   - Hash or concatenate history for unique node identification
   - Used for caching and debugging

3. `isTerminal(history: string[], config: TreeConfig): boolean`
   - Returns true if:
     - Both players have acted and one folded
     - Showdown reached (both players all-in or action closed)
     - Action sequence complete for street

4. `getAvailableActions(history: string[], config: TreeConfig): string[]`
   - Based on game state, return valid actions
   - Preflop: FOLD, CALL, RAISE_{size} for various sizes
   - Include all-in when appropriate
   - Actions must be deterministic (sorted)

5. `computeTerminalUtility(history: string[], hands: [CanonicalHand, CanonicalHand], config: TreeConfig): [number, number]`
   - For fold: folder loses pot equity, other player wins
   - For showdown: compare hands, split pot by equity
   - Returns utilities in BB

6. `createDecisionNode(history: string[], player: Player, hand: CanonicalHand, config: TreeConfig): DecisionNode`
   - Creates decision node with lazy getChild function
   - getChild generates child on first access, caches result

7. Helper: `getNextPlayer(currentPlayer: Player): Player`
   - Returns `1 - currentPlayer` (alternates between 0 and 1)

Key implementation detail: Use closures for lazy child generation. Each node holds a `Map<string, GameNode>` cache for children, populated on first getChild call.
