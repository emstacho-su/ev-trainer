  <name>Task 2: Implement postflop card abstraction (E[HS])</name>
  <files>src/lib/solver/abstraction/cards.ts</files>
  <action>
Extend card abstraction for postflop:

1. `calculateEHS(hand: Hand, board: Card[], iterations?: number): number`
   - E[HS] = Expected Hand Strength
   - Monte Carlo: for each possible opponent hand and runout, compute win rate
   - Returns 0.0 to 1.0 (hand strength percentile)

2. `PostflopBucket` type:
   ```typescript
   interface PostflopBucket {
     id: number;
     range: [number, number]; // EHS range [low, high)
   }
   ```

3. `getPostflopBuckets(numBuckets: number): PostflopBucket[]`
   - Default: 50 buckets (0-2%, 2-4%, ..., 98-100%)
   - Uniform distribution initially
   - Can be refined with k-means later

4. `assignBucket(ehs: number, buckets: PostflopBucket[]): number`
   - Returns bucket ID for given EHS
   - Binary search for efficiency

5. `buildPostflopInfoSetId(player: Player, bucket: number, board: string, history: string[]): string`
   - Postflop info set uses bucket instead of canonical hand
   - Board represented as sorted card string (e.g., "AhKc2d")

6. Card removal for postflop:
   - `getValidHands(board: Card[]): Hand[]`
   - Returns all hands not blocked by board cards
  </action>

Create postflop solver using CFR+ core:

1. `PostflopConfig` interface:
   ```typescript
   interface PostflopConfig extends CFRConfig {
     street: Street;
     board: Card[];
     heroRange: CanonicalHand[];  // Range hero arrives with
     villainRange: CanonicalHand[]; // Range villain arrives with
     potBb: number;
     stackBb: number;
     heroPosition: PositionRelative; // 'IP' or 'OOP'
     actionAbstraction: ActionAbstractionConfig;
     numBuckets: number; // E[HS] buckets (default 50)
   }
   ```

2. `createPostflopTree(config: PostflopConfig): ChanceNode`
   - Root deals remaining board cards (turn/river if needed)
   - Decision nodes use bucket-based info sets
   - Terminal nodes evaluate hand strength

3. `PostflopSolution` interface (similar to PreflopSolution):
   ```typescript
   interface PostflopSolution {
     strategies: Map<string, number[]>;
     result: CFRResult;
     board: Card[];
     street: Street;
   }
   ```

4. `solvePostflopSubgame(config: PostflopConfig): PostflopSolution`
   - Reuses cfrTraverse from preflopSolver (or shared cfr.ts)
   - Uses E[HS] bucketing for info sets
   - Returns strategies keyed by bucket-based info set IDs

5. `toSolverNodeOutputPostflop(hand: Hand, board: Card[], solution: PostflopSolution): SolverNodeOutput`
   - Maps specific hand to bucket
   - Looks up strategy for that bucket's info set
   - Returns SolverNodeOutput format

Key difference from preflop: Uses buckets instead of canonical hands, requires board cards.
