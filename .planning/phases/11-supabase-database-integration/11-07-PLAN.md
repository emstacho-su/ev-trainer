Output: Spot service module, seed script, and updated pack loader to read from Supabase.
</objective>

<task type="auto">
  <name>Task 1: Create spot service and seed script</name>
  <files>
    src/lib/supabase/spotService.ts
    scripts/seedSpots.ts
  </files>
  <action>
    1. Create `src/lib/supabase/spotService.ts`:

       **Query functions:**

       a. `getFilteredSpots(supabase, filters)`:
          - Query spots table with filters applied:
            * street (eq filter)
            * hero_position (in filter for multiple positions)
            * pot_type (in filter for multiple pot types)
            * effective_stack_bb range (gte/lte)
            * scenario_type (eq filter, optional)
            * tags (contains filter via GIN index)
            * is_system = true (default -- only show system spots unless user's own)
          - Order by created_at or random (for training variety)
          - Limit to N spots (default 50)
          - Return array of spot rows

       b. `getSpotById(supabase, spotId)`:
          - Query spots WHERE spot_id = x
          - Return single spot or null

       c. `getRandomSpots(supabase, filters, count, seed?)`:
          - For deterministic training: use seed to compute offset
          - Query filtered spots with LIMIT and deterministic ordering
          - This replaces the existing spotSource.ts deterministic selection

       d. `createSpot(supabase, spotData)`:
          - Insert into spots table
          - Set created_by to current user
          - Set is_system = false
          - Return created spot

       e. `convertSupabaseSpotToEngineSpot(row)`:
          - Convert Supabase spots table row to engine Spot type
          - Map column names to engine field names
          - Parse JSONB fields (stacks_bb)
          - This bridge function ensures the engine layer doesn't need changes

       f. `convertEngineSpotToSupabaseRow(spot, meta)`:
          - Reverse conversion for seeding
          - Map engine Spot + SpotMeta to spots table row format

    2. Create `scripts/seedSpots.ts`:
       - Read existing pack JSON files from public/packs/
       - For each spot in the pack:
         * Convert to Supabase spots table row format
         * Set is_system = true
         * Generate tags from position, street, pot type, stack depth
         * Generate spot_id from deterministic hash of spot data
       - Upsert into Supabase spots table (ON CONFLICT spot_id DO UPDATE)
       - Use Supabase service role key for seeding (bypasses RLS)
       - Add script to package.json: `"seed:spots": "npx tsx scripts/seedSpots.ts"`
       - Log progress: "Seeded X spots into Supabase"

    **Important:** The service role key (SUPABASE_SERVICE_ROLE_KEY) is needed ONLY for the seed script. It should be in .env.local but NEVER exposed to the browser. Add to .env.example with a comment.
  </action>
  <verify>

    - spotService.ts exports all functions
    - scripts/seedSpots.ts can be run with `npx tsx scripts/seedSpots.ts`
    - Conversion functions map between Supabase row and engine Spot type correctly
  </verify>
  <done>Spot service provides filtered queries against Supabase spots table. Seed script populates spots from existing pack data. Conversion functions bridge Supabase rows and engine Spot types.</done>

         * Calls spotService.getFilteredSpots()
         * Converts results to engine Spot[] via convertSupabaseSpotToEngineSpot()
         * Returns in the same format as the existing loadBundledPack()

    2. The existing `loadBundledPack()` function should remain as a fallback for:
       - Guest users (no Supabase auth)
       - Development without Supabase configured
       - Cases where Supabase is unreachable

    3. Create a unified spot loading function:
       ```typescript
       export async function loadSpots(
         filters: SpotFilterInput,
         supabase?: SupabaseClient
       ): Promise<Spot[]> {
         if (supabase) {
           try {
             return await loadSpotsFromSupabase(supabase, filters)
           } catch {
             // Fallback to bundled pack
           }
         }
         return loadBundledPack(filters)
       }
       ```

    4. Update sessionHandlers or session routes to use loadSpots() with the Supabase client when available.

    **Do NOT remove the bundled pack fallback.** It's needed for:
    - Guest users
    - Local development without Supabase
    - Resilience if Supabase is temporarily unavailable
