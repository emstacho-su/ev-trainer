<objective>
Create the postflop solver bridge: a mock solver for development, a client module the UI calls, and a backend API route.

Purpose: The UI needs an async interface to get solver output for a given board/street. The mock solver provides realistic data during development without running full CFR+ iterations (which are slow and cause test flakiness). The API route enables server-side solving when needed.

Output: mockPostflopSolver.ts (deterministic mock), solverClient.ts (async interface), /api/postflop/solve route.

Note on Web Workers: The RESEARCH.md recommends Comlink + Web Worker. However, Next.js 16 with App Router has Worker bundling complexity that risks blocking progress. Use direct async function call in solverClient.ts for Phase 10. Worker can be added as an enhancement in a future phase if performance issues arise. The mock solver is fast enough (< 1ms) and the real solver can be called async in a useEffect.
</objective>
