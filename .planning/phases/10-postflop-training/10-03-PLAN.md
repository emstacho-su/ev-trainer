  <behavior>
    PostflopSessionState shape:
    {
      machineState: PostflopMachineState;  // 'idle' | 'deciding' | 'evaluating' | 'advancing' | 'summary'
      currentStreet: Street;              // 'FLOP' | 'TURN' | 'RIVER'
      board: Card[];                      // grows: 3 -> 4 -> 5
      heroHand: [Card, Card] | null;
      potBb: number;
      stackBb: number;
      heroPosition: 'IP' | 'OOP';
      decisions: Partial&lt;Record&lt;Street, StreetDecision&gt;&gt;;   // StreetDecision from types.ts
      deviatedStreet: Street | null;      // first street where user went off-line
      summary: HandSummaryData | null;
    }

    Actions:
    - START_HAND({ heroHand, board, potBb, stackBb, heroPosition }): machineState='deciding', currentStreet='FLOP', board=board.slice(0,3), decisions={}, deviatedStreet=null
    - USER_DECIDED({ actionId }): machineState='evaluating', sets decisions[currentStreet]={ actionId, solverOutput: null, isOnSolverLine: true }
    - SOLVER_OUTPUT({ output }): machineState='advancing', fills decisions[currentStreet].solverOutput, checks if user action is in solver output with frequency > 0.01; if not, sets deviatedStreet=currentStreet (only if not already set). isOnSolverLine=false if deviated
    - ADVANCE_STREET({ nextBoard }): transitions currentStreet (FLOP->TURN, TURN->RIVER); if currently RIVER, sets machineState='summary' and builds HandSummaryData; otherwise sets machineState='deciding' and updates board to nextBoard
    - RESET(): returns to initialPostflopState

    Test cases:
    1. START_HAND transitions to deciding, resets decisions
    2. USER_DECIDED transitions to evaluating with actionId set
    3. SOLVER_OUTPUT with matching action: isOnSolverLine=true, no deviatedStreet
    4. SOLVER_OUTPUT with non-matching action: isOnSolverLine=false, deviatedStreet='FLOP'
    5. ADVANCE_STREET from FLOP: currentStreet='TURN', machineState='deciding'
    6. ADVANCE_STREET from RIVER: machineState='summary', summary is populated
    7. Deviation on FLOP: TURN and RIVER decisions should still be recorded (user continues playing) but isOnSolverLine=false for those streets too (handled in UI, not reducer — reducer tracks only deviatedStreet)
    8. RESET returns to idle state

    Use 'isOnSolverLine' on StreetDecision to indicate whether user matched solver.
    deviatedStreet is the FIRST street of deviation — subsequent streets can check deviatedStreet !== null.
  </behavior>
