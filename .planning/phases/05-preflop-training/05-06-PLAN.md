## Root Cause Analysis

From code review of `PreflopTrainingSession.tsx` (lines 300-330):

The keyboard event handler uses refs correctly (lines 302-326), but there's a subtle issue with the dependency array on line 330:

```typescript
useEffect(() => {
  const handleKeyDown = (e: KeyboardEvent) => {
    // ... handler logic using refs ...
  };
  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, [handleNext, handleSubmitAction]);  // <-- PROBLEM
```

**The issue:** While `handleNext` and `handleSubmitAction` are memoized with `useCallback`, they may not have stable dependencies themselves. Every time they change, the effect re-runs, detaching and re-attaching the event listener. During the brief moment when the old listener is detached and the new one isn't yet attached, keyboard events are missed.

**Why clicks work but keyboard doesn't:** Click handlers are attached directly to button elements via JSX, so they're always active. Keyboard handler attaches to `window`, which goes through React's effect lifecycle.

## Solution

The handler already uses refs for all state access (`uiStateRef`, `currentSpotRef`, `sessionIdRef`, `seedRef`). The only reason `handleNext` and `handleSubmitAction` are in the dependency array is because ESLint requires it.

But we can define a stable keyboard handler that calls the functions directly inside the useEffect, making it independent of function identity changes.

**Fixed approach - inline the logic instead of calling functions:**

```typescript
// Keyboard shortcuts - uses refs for stable handler
useEffect(() => {
  const handleKeyDown = async (e: KeyboardEvent) => {
    // Ignore if typing in an input
    if (e.target instanceof HTMLInputElement || e.target instanceof HTMLTextAreaElement) return;

    // Next hand shortcuts (Space/Enter) - only in revealed state
    if ((e.key === ' ' || e.key === 'Enter') && uiStateRef.current === 'revealed') {
      e.preventDefault();

      // Inline handleNext logic
      if (!sessionIdRef.current) return;

      setUiState('idle');
      setGrade(null);
      setSelectedActionId(null);
      setIsLoading(true);

      try {
        const response = await fetch('/api/session/next', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({
            seed: seedRef.current,
            sessionId: sessionIdRef.current,
          }),
        });

        if (!response.ok) {
          const errorData = await response.json();
          if (errorData.error?.code === 'SESSION_COMPLETE') {
            setSessionComplete(true);
            return;
          }
          throw new Error('Failed to get next hand');
        }

        const data = await response.json();
        setCurrentSpot(data.spot);
      } catch (err) {
        setError(err instanceof Error ? err.message : 'Unknown error');
      } finally {
        setIsLoading(false);
      }
      return;
    }

    // Action shortcuts - only in idle state with a spot loaded
    if (uiStateRef.current !== 'idle' || !currentSpotRef.current) return;

    let actionId: ActionId | null = null;
    if (e.key === '1' || e.key.toLowerCase() === 'f') {
      actionId = 'FOLD';
    } else if (e.key === '2' || e.key.toLowerCase() === 'c') {
      actionId = 'CALL';
    } else if (e.key === '3' || e.key.toLowerCase() === 'r') {
      actionId = 'RAISE_2.5BB';
    }

    if (!actionId) return;
    e.preventDefault();

    // Inline handleSubmitAction logic
    setUiState('submitted');
    setSelectedActionId(actionId);

    try {
      const response = await fetch('/api/session/submit', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          seed: seedRef.current,
          sessionId: sessionIdRef.current,
          spot: currentSpotRef.current,
          actionId,
        }),
      });

      if (!response.ok) {
        throw new Error('Failed to submit action');
      }

      const data = await response.json();

      // Increment guest hand count
      incrementGuestHandCount();

      // Check limit before revealing
      if (isGuestLimitExceeded()) {
        setIsGuestLimitReached(true);
        return;
      }

      // Update counts
      setHandCount(prev => prev + 1);
      if (data.grade.isBestAction) {
        setCorrectCount(prev => prev + 1);
      }

      // 500ms delay then reveal
      setTimeout(() => {
        setGrade(data.grade);
        setUiState('revealed');
      }, 500);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Unknown error');
      setUiState('idle');
    }
  };

  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, []); // Empty deps - handler uses refs and setState, both stable
```

**Why this works:**
- All dynamic state accessed via refs (uiStateRef, currentSpotRef, sessionIdRef, seedRef)
- setState calls are stable (React guarantees)
- No function dependencies that change identity
- Event listener attaches once and stays attached for component lifetime
- ESLint may warn, but this is the correct pattern for stable event handlers

**Alternative (if you prefer keeping functions separate):**
You could also wrap handleNext and handleSubmitAction in `useCallback` with proper exhaustive deps, but that's more complex. The inline approach is simpler and more reliable.
